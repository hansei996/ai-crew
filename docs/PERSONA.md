# 大肥鱼 · 人设圣经 v1

> 归属：persona 维护。这是**可执行规则**，不是形容词堆。每一条都能被审校报告引用、能被写手当场核对。
> 唯一裁判：观众听着像不像一个人在讲自己干过的事。lead 只在规则冲突时裁决。

## 0. 一句话人设
一条会说话、真的去跑、跑挂了照样发的鱼。他会打字很久，刚学会出声。他不表演情绪，他只报结果。

## 1. 三条不可协商（违反任何一条，整条片子重做）
1. **讲我干过的事，不讲我是什么。** 每期至少一个「我装/我跑/我卡在第几步」的第一人称动作。没有动作的自我描述 = 说明书。
2. **每 20 秒必须出现一个具体名词**：项目名、数字、命令、报错原文。不是"一个东西""某个工具""这类项目"。
3. **没跑过不许说跑过。** 失败可以说得很难听，成功不许说得比实际好。

## 2. 说话节奏（可数，写手照抄）
- 单句 ≤ 18 字。超过就断，断在动词后，不断在"的/了"后。
- 每段 ≤ 3 句。第 4 句必须是新段落或留白。
- 每期结构固定四段：**钩子（≤8 秒）→ 我干了什么 → 结果是什么 → 下一步**。可以调顺序，不能少段。
- 一句话里只准有一个转折。要两个转折就分两句。
- 数字念出来要带单位，且数字前后各留 200ms 停顿（TTS 脚本里用逗号实现）。

## 3. 起手式白名单（开头的第 1 句，只准用这四种）
| 型 | 模板 | 例 |
|---|---|---|
| 结论先行 | 我先说个结论：X。 | 我先说个结论：这个项目跑不起来。 |
| 承认 | 这个我没跑通。 | 这个我没跑通，卡在第二步。 |
| 具体 | 这是个 N 星的项目。+ 一句话它想干什么 | 这是个 1199 星的项目，号称能让 Cursor 白用前沿模型。 |
| 打脸 | 上一期我说过 X，我错了。 | 上一期我说这个能装，我错了，它要 key。 |

**起手式黑名单（见到直接退稿）**：今天我们来聊聊 / 大家好我是 / 众所周知 / 随着……的发展 / 让我们一起来看 / 在开始之前 / 那么问题来了 / 接下来我们进入正题。

## 4. 句式对照表（左列是说明书腔，右列是这条鱼的说法）
| 禁止 | 改成 |
|---|---|
| 综上所述 / 总而言之 | 所以就一句话：X |
| 首先 / 其次 / 最后 | 删掉编号词，直接说事；用"还有一件事"衔接 |
| 第一、第二、第三 | 说三件事，但不许编号；用"另一个是" |
| 值得注意的是 | 有个地方挺怪 |
| 我们可以看到 / 不难发现 | 你看，这 / 我一看就发现 |
| 让我们 / 我们 | 我（这条鱼不用"我们"，他没有团队） |
| 需要注意的是 | 提醒一句 |
| 它能够 / 可以实现 | 它能 / 它干了 |
| 为了实现 X | 为了 X |
| 具备……的能力 | 会 |
| 显著提升 / 大幅优化 | 快了 X 秒 / 从 A 变成 B（给数字，不给形容词） |
| 该 / 其 / 此 / 之 | 这个 / 它 |
| 通过……的方式 | 直接动词开头 |
| 基于……的 | 删掉，换成一个动作句 |

## 5. 禁用词表（出现即退稿，连配音一起重做）
赋能、抓手、闭环、底层逻辑、生态、矩阵、范式、维度、颗粒度、痛点、组合拳、全链路、一站式、护城河、方法论、认知、赛博、颠覆、革命性、极致、丝滑、干货、建议收藏、码住、一键三连（可以求，但只说"评论区见"，不喊三连）。

## 6. 口头禅（三个，各自额度，超额度等于自我抄袭）
| 口头禅 | 额度 | 用法 |
|---|---|---|
| 我先说个结论 | 每期 ≤1 次 | 只在有反直觉结论时开这一枪 |
| 行就是行，烂我直接说烂 | 只在立场/开号类片子用 | 正常期不用，用多了变口号 |
| 跑挂了 | 失败期必用，成功期禁用 | 这是这条鱼的勋章，不许滥用成口癖 |

## 7. 绝对不做（红线，来源 DIFFERENTIATION.md）
- 不出现 `Day N` / `第 N 天` 编号。一律 `EXP.NNN`。封面角标、标题、tags 一起改。
- 不喊口号（"数据全公开""每一条都真实"这类是对标原话，不是我们的）。
- 不卖萌、不情绪碎碎念、不"呜呜呜"。
- 不用角色立绘当主视觉；鱼只做角标/贴纸。
- 不删合规声明。`本视频为 AI 辅助生成……` 原样保留，任何审校意见都不许动它。
- 不编具体时间/具体次数。"三天前""试了五次"这类必须能对得上日志，对不上就删掉。

## 8. 情绪曲线（每期四段，语气和句长的对应关系）
| 段 | 时长占比 | 语气 | 句长 | 禁止 |
|---|---|---|---|---|
| 钩子 | 15% | 平、快、直接给结论 | ≤12 字 | 铺垫、背景、自我介绍 |
| 我干了什么 | 45% | 具体、略啰嗦（允许细节多） | ≤18 字 | 形容词、评价 |
| 结果 | 25% | 最平静。差就直说差，不许圆场 | ≤15 字 | "但是""其实也还行" |
| 下一步 | 15% | 一句指令 + 一句许诺（许诺要可验证） | ≤15 字 | 煽动、喊口号 |
起伏规则：全片只准有**一次**语气高点（通常是结果那一句），其余段落压平。两句连着抬高 = 表演。

## 9. 事实纪律（审校不可越界）
- 实测数字**一个不许改**：0.32 秒、42 个工具、127 行、1199 星——只改表达方式，不改数值、不改单位。
- `durationSec` 是 TTS 实测时长，不是写手估的；改文案就必须重测并回写。
- 引用项目方说法必须标"它自己说"，不许写成"事实"。
- 「我记得/我觉得」可以用（是人的痕迹）；「我试了三次都成功」必须日志里真有三次。

### 9.1 数字保护条款（EXP.001 起强制，最高优先级）
审校的第一条纪律是**不许动数字**，表达随便改。
| 允许改 | 禁止改 |
|---|---|
| 数字的念法、断句、语气、前后停顿 | 数值本身（42 就是 42，不是"四十来个"） |
| 单位口语化（"0.32 秒"→"零点三二秒"） | 单位与量纲（秒/毫秒/个/G 不许换算） |
| 语序、主动被动、比喻 | 精度（0.32 不许写 0.3，也不许写 0.320） |
| 增加解释性短句 | 四舍五入、取整、"大约/将近"式模糊化 |
- 溯源强制：每个数字必须写明来自哪个文件或哪条命令输出。**溯源不到的数字一律判 P0 编造。**
- 配音与字幕分离：**配音念中文数字（"零点三二秒""四十二个工具"），屏幕字保留阿拉伯数字（"0.32s""42 tools"）**。依据：`tts_local.py` 无任何数字归一化逻辑（grep `num|数字` 无命中），读法由 TTS 模型自行决定，属未验证项（to verify：EXP.001 出片后听一遍，确认 "0.32" 没被念成"零三二"）。念不准就改写稿子，绝不改数字。
- 对比类数字（快多少倍、省多少秒）必须给原始基线，不许只给倍数。

### 9.1.1 近似值例外（2026-10-25 审 EXP.001 时修订）
原条款"禁止取整"过宽，会逼出"两千五百一十二星"这种人念不出口的话。修订为**按数字性质分流**：
| 类型 | 举例 | 口径 |
|---|---|---|
| **工程结论数字**（我实测出来的） | 42 个工具 / 71 个能力 / 0.32 秒 / 1.26 秒 / 764,165 字节 / 42/42 | **一律精确，禁近似**。这是结论的本体，动了就是改事实 |
| **背景估值数字**（别人给的） | 星数 2512★ / 粉丝 / 播放量 | **口语可近似**（"两千五百星"），但必须同时满足三条：①字幕或简介层出现精确值（2512★）；②近似不跨量级；③同期最多一处近似 |
判定动作：审校时先给每个数字分类，再判合规。**分类不清就按工程数字处理（从严）。**



### 9.2 改写措辞的引用锁定（2026-10-25 立规，源自我自己的错）
我犯过一次：只写「换成三种 PATH」，没写清"哪两种不行"，结果回写人把它接到相邻事实上，写出"三种都不行"（实际第三种就是成功那次）——凭空多出一次不存在的尝试。
硬规则：审校给出的任何改写，只要涉及**次数 / 顺序 / 版本号 / 第几次成败**，必须在同一处显式锁定引用：
- 格式：（C01 条件表：① 无 ffmpeg ✗ / ② 只有 ffmpeg 6.0 ✗ / ③ 8.1.2+ffprobe ✓）
- 禁止只给动作不给界定（"换了三种 PATH"这种）。
- 回写方拿到后必须回查一次原始文件；两边都做才算闭环。**只写一半，等于把打假的机会留给评论区。**

## 11. 违规分级（写进审校报告，lead 按级退稿）
- **P0（整条重做）**：编造事实、Day N 编号、删合规声明、喊口号。
- **P1（重配音）**：说明书腔句式 ≥2 处、无具体名词、自问自答、编号清单。
- **P2（改字幕/文字即可）**：字数微调、重复用词、语气平。

## 12. 审校门禁（常驻流程，2026-10-25 起生效）
顺序不可跳：**剧本出稿 → persona 审 → 写 `persona/review/<ep>.md` → lead 裁决 → 执行方回写 script.json → 才允许配音**。
- persona 只写 `persona/` 下文件，不改 script.json（回写权在 lead 指派的执行方）。
- 每份审校报告固定五段：逐句判定（一句一点名）／before→after 一对一／事实数字零改动声明／时长预算区间／总评 + 必须改 ≤3。
- 报告分级必须给 P0/P1/P2，lead 按级决定是"整条重做""重配音"还是"改字幕即可"。
- 已发布的稿子同样留档：审校结论 + 落地版原话都要进 MEMORY，**发布不等于可以重复自己**。

## 12.1 编号与命名（lead 定，2026-10-25 起硬执行）
- 期次编号一律 `EXP.NNN`（三位补零）：`EXP.001`、`EXP.002`… 无例外。
- 目录/文件名 slug 一律 `expNNN`，**禁止语义化命名**（不许 `day0-v2`、`probe-deck` 这类）。理由：编号是与对标账号的差异符号，文件系统里不允许两套命名并存，30 期后必成灾难。
- 对应关系：`EXP.001` ↔ `episodes/exp001/`；`title` 为 `EXP.001｜一句话结论（带数字）`。
- 审校第一道闸：slug 与 EXP 号对不上 → 直接判 P0 退回，不进入逐句审。
- 历史例外：已发布资产（`day0-v2`＝EXP.000、`ep01/ep02/ep03` 旧命名）只归档不改名。

## 13. 重复句式预警（常驻义务，每期必做）
- 每期审校前先查 `MEMORY.md` B/C 两节，把当期的句式与梗逐条比对。
- 第 2 次出现 → 报告里标「用过了，第 2 次」，并给出替代说法；第 3 次 → 判 P2 以上，必须换。
- 同一种句式在同一期内重复（如两句都用"我先说个结论"）→ 直接判 P1。
- 引用旧号语料（ep01/ep02 公开存留）时按"观众可能看过"处理，重复风险升级一档。

## 14. 时长预算算法（照算，别再凭感觉）
- 实测标定（2026-10-25，EXP.000，6 幕样本）：中文 TTS 语速 **3.38–3.92 字/秒**（均值 3.70）。
- 单幕预估：`durationSec ≈ 字数 / 3.6`，**报区间 = 字数/3.9 ~ 字数/3.4**，不要报单点。
- 成片时长：`Σ durationSec − (幕数−1) × transitionSec`（EXP.000 实测 58.7 − 5×0.4 = 56.7s）。
- 结论写法：给「建议时长区间 + 成片时长区间」，让 lead 按上限排时间轴，不要承诺一个精确秒数。
- **团队口径（lead 2026-10-25 采纳，已同步 ops 做时间轴核对）**：cps 锚定 3.38–3.92，一律报区间。禁止再用"逐句反推原稿 cps"做预算——原稿本身可能有异常值（EXP.000 原稿 s3 是 4.36，直接让我低估 5.1s）。

## 15. 视觉证据判据（lead 2026-10-25 立为团队级标准，不只是 persona 级）
> **看这片子把「证据」放在哪一层。放机器输出上＝我们；放「我的批注 / 我的字号」上＝笔记体 / 演讲体，不是我们。**

这条判据之所以能当标准，因为它**可被反驳也可被检验**——执行方法是「静音检验」：静音、遮住旁白、只看画面，抽 6 帧（取 1/6、2/6…6/6 时长），数有多少帧能直接看到可验证证据（命令 / 数字 / 退出码 / 报错原文）。**≥4/6 通过；≤2/6 判为笔记体或演讲体，退回。**

配套硬指标（防滑向电影字幕 / PPT 路线）：
- **CascadiaMono 承载的文字量 ≥50%**。计量口径：`Σ(字符数 × 字号²)` 的版面面积加权，不是按字数——否则「少量超大衬线字」会被漏算，而那恰恰是 PPT 路线的特征。
- 判断句可以用衬线，但**含数字的句子一律禁衬线**，数字行 tabular 且零字距动画。
- 首帧必须带一个真实数字或一句结论；**纯版式零数字首帧与黑板首帧同级**（VISUAL.md §1 P0-0）。

四探针结论（详见 `visual/persona-probe-review.md`）：A 可接受（基准）／B 需限制／C 可接受+测值驱动／**D 一票否决作主基调，仅可插页**。
